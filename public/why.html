Why ClosedVPS closes every port

Each thing ClosedVPS sets up on a new server is below, with the standard or vendor document that asks for it, the line itself, and where ClosedVPS does less than the document. It starts with the bug that made this matter in October 2026.

What happened in October

A bug in how Linux handles TCP turned into a way to take over servers from the internet, and Ubuntu needed two weeks after that to ship a fix.

15 Oct
A kernel fix goes out

For CVE-2026-98432, a bug in Linux since 4.4, with no word yet on how bad it is.

27 Oct
Remote root is shown

Anthropic runs commands as root on a server with a Multipath TCP listener, with no login.

10 Nov
Ubuntu ships the fix

A fixed kernel for 24.04 in USN-9022-1, 14 days after the exploit was public.

by 12 Nov
ClosedVPS servers run it

The daily update installs it, and the server reboots into it at 04:00 UTC.

The advisory on oss-security warned that servers without a Multipath TCP listener might be open to similar attacks. Until the fix, Ubuntu's advice was a firewall rule to drop the packets the attack uses. A server behind a Hetzner firewall with no inbound rules never got those packets in the first place.

A firewall with no inbound rules

ClosedVPS creates a Hetzner Cloud firewall with no inbound rules and attaches it when it creates the server, so it's in place before the first boot. Everything coming in is dropped. Outgoing traffic stays open, which NIST describes as the usual practice.

Generally, firewalls should block all inbound and outbound traffic that has not been expressly permitted by the firewall policy. [...] This practice, known as deny by default, decreases the risk of attack.

NIST SP 800-41 Rev. 1, section 4

If you don't define any rules here, all inbound traffic will be dropped.

Hetzner Docs, Cloud Firewalls FAQ

Hetzner's firewall doesn't filter Hetzner's private networks. ClosedVPS doesn't put servers on one.

SSH only over Tailscale

Port 22 is never open to the internet. You reach the server over Tailscale, which connects outward from the server. CISA's directive BOD 23-02 makes US federal agencies take management interfaces off the internet and recommends the same to everyone. It names devices like routers and server consoles, and a server's SSH is the same kind of door, though the directive doesn't list it.

Remove the interface from the internet by making it only accessible from an internal enterprise network.

CISA BOD 23-02, required actions

While BOD 23-02 strictly applies to FCEB agencies, this threat extends to every sector. CISA recommends all stakeholders review and adopt this guidance.

CISA alert, 13 June 2023

No root login, no passwords

Root can't log in over SSH, and only the user ClosedVPS creates can (AllowUsers). Those are rules 5.1.20 and 5.1.4 of the CIS Ubuntu Linux 24.04 Benchmark. CIS has no rule against password login, only against empty passwords (5.1.19). ClosedVPS turns passwords off anyway, so only your SSH key gets in.

Disallowing root logins over SSH requires system admins to authenticate using their own individual account, then escalating to root.

CIS Ubuntu Linux 24.04 LTS Benchmark v2.0.0, 5.1.20 Ensure sshd PermitRootLogin is disabled

Security updates that reboot

Ubuntu installs security updates once a day by itself but never reboots, so a fixed kernel waits until someone restarts the server. ClosedVPS turns the reboot on, at 04:00 UTC and only when an update needs it.

There is no way that an organization can keep up with patching without automation. [...] Automation is also needed for emergency situations, like patching a severe vulnerability that attackers are actively exploiting.

NIST SP 800-40 Rev. 4, section 3

The default value is false.

Ubuntu Server docs, Automatic updates, on Automatic-Reboot

Docker ports stay on the server

Docker writes its own firewall rules, and its docs warn that they go around a host firewall like ufw. ClosedVPS sets Docker to publish ports on 127.0.0.1, for single containers and for the networks Compose makes, using the two settings Docker documents for it. The Hetzner firewall already keeps those ports off the internet, and this keeps them off your tailnet too unless you publish one on purpose.

Docker and ufw use firewall rules in ways that make them incompatible with each other. [...] Packets are routed before the firewall rules can be applied, effectively ignoring your firewall configuration.

Docker Docs, Packet filtering and firewalls

Publishing container ports is insecure by default.

Docker Docs, Port publishing and mapping

Websites through Cloudflare Tunnel

A site you want public goes through Cloudflare Tunnel, which also connects outward, so the firewall stays shut.

You can then configure your firewall to allow only these outbound connections and block all inbound traffic, effectively blocking access to your origin from anything other than Cloudflare.

Cloudflare docs, Cloudflare Tunnel

Where it stops short of CIS

CIS Level 1 also wants ufw switched on with incoming traffic denied (4.1.1 to 4.1.5), and a long list of SSH settings such as allowed ciphers, a login banner and MaxAuthTries. ClosedVPS leaves those at Ubuntu's defaults and relies on the Hetzner firewall in front of the server, so a CIS audit of a fresh server would still flag them. If you need a clean audit, Ubuntu Pro's Ubuntu Security Guide applies the benchmark on top.
