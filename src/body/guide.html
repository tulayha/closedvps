How to lock down a Hetzner VPS by hand

These steps give a new Hetzner server no open ports, SSH only over Tailscale and automatic security updates. ClosedVPS does this in one command, adds a non-root user, and keeps trying while Hetzner is sold out. The server joins Tailscale on its first boot, so port 22 is never open to the internet. If you lock yourself out, add an inbound rule for TCP 22 from your own IP to the firewall, SSH to the public IP, fix Tailscale and delete the rule. On a server that's already running, install Tailscale and SSH in over it before you attach the firewall.

1. Make the firewall first

In the Hetzner Console open Firewalls, Create Firewall, delete the SSH and ICMP rules it suggests, and save. A Hetzner firewall with no inbound rules drops every incoming packet. Outbound stays open (Hetzner's firewall FAQ).

2. Create the server with Tailscale in its first boot

First make the policy change in Tailscale for a VPS, so the server can't reach your other devices. Then make a one-off, pre-approved auth key with the tag tag:closedvps at login.tailscale.com/admin/settings/keys. Create the server with your SSH key, the new firewall selected, and this under Cloud config. A tagged server never hits key expiry, so it stays on your tailnet.

#cloud-config
runcmd:
  - curl -fsSL https://tailscale.com/install.sh -o /tmp/ts.sh
  - sh /tmp/ts.sh
  - tailscale up --auth-key=tskey-auth-XXXX --hostname=vps

3. Turn off SSH passwords

Then ssh root@vps and run:

cat > /etc/ssh/sshd_config.d/10-local.conf <<'END'
PasswordAuthentication no
KbdInteractiveAuthentication no
END
systemctl restart ssh

4. Let security updates reboot it

Ubuntu already installs security updates every day. A kernel update only takes effect after a reboot, so let it reboot at 04:00 UTC when one is needed:

cat > /etc/apt/apt.conf.d/52reboot <<'END'
Unattended-Upgrade::Automatic-Reboot "true";
Unattended-Upgrade::Automatic-Reboot-Time "04:00";
END

5. Serve websites through Cloudflare Tunnel

In the Cloudflare dashboard go to Networking, Tunnels, Create a tunnel, and run the install command it shows on the server. Then on the tunnel's Routes tab add a published application with the service URL http://127.0.0.1:3000 (your app's port). The tunnel connects outward, so the firewall stays shut.
