Tag your VPS so it can't reach your laptop over Tailscale

A new tailnet lets every device reach every other one. Put a VPS on it and the VPS can open connections to your laptop, your phone and your NAS, while a server running Claude Code installs packages and runs code you haven't read. Two changes to the tailnet policy let your devices reach the server and stop the server from starting connections to them. Each ClosedVPS server asks for the tag when it joins, and ClosedVPS warns when one joins without it.

Why a VPS can reach your laptop

Tailscale starts every tailnet with a policy that allows everything:

Lets all devices in the tailnet access all other devices in the tailnet.

Tailscale docs, policy samples

That suits your own laptop and phone. A VPS pulls packages and downloads from the internet all day, and if something on it is taken over, the tailnet is a way into your other machines that no firewall in front of the server can stop.

Change the policy

Open Access controls in the Tailscale admin console, add the tag, and change who may start connections from everyone to the people in your tailnet:

"tagOwners": { "tag:closedvps": ["autogroup:admin"] },
"grants": [
  // was "src": ["*"]
  {"src": ["autogroup:member"], "dst": ["*"], "ip": ["*"]},
],

A tagged device belongs to its tag instead of a person, so autogroup:member leaves it out. An older tailnet whose file has acls in place of grants changes the src of its allow-everything rule the same way. The ssh section stays as it is. If you already tag other devices, such as a home server, they lose the right to start connections too, so give them their own rule.

The auth key

In Settings, Keys, choose Generate auth key. If your tailnet asks you to approve new devices, turn on Pre-approved. Leave Reusable off for one server. For several at once with --count, turn it on and let the key expire within a day. Paste it when closedvps create asks, or set it as TS_AUTHKEY. The key needs no tag of its own, since the server asks for tag:closedvps itself, which the policy above allows. Setting a server up by hand, turn on Tags and pick tag:closedvps, and use the key in the guide's tailscale up line.

Or save an OAuth client

If you buy servers often, or wait for stock for days, closedvps setup can save a Tailscale OAuth client in its last step. ClosedVPS then makes a one-off tagged key for each server at the moment it buys, and checks before buying that your policy has the tag and keeps it away from your devices. In the admin console open Settings, Trust credentials, choose Credential, then OAuth, and give it these scopes:

  • Auth Keys, write, with the tag tag:closedvps
  • Policy File, read
  • Devices, read

If it leaked, it could add devices tagged tag:closedvps and read your policy and device list. It can't reach your devices or change the policy. On a machine without a password store, such as a container, pass it as TS_OAUTH_CLIENT_ID and TS_OAUTH_CLIENT_SECRET.

Tag a server that's already running

On the Machines page, open the menu at the end of the server's row, choose Edit tags, add tag:closedvps and save. Only an Owner, Admin or Network admin can do this, and the tag has to be in the policy first (Tailscale docs, tags).

What changes

Your devices still reach the server, and its answers still get back to them. Only new connections from the server are blocked:

A grant is necessary to open a new connection, but not to reply to one.

Tailscale docs, grants explained

The server also stays on your tailnet for good, since tagged devices skip the 180-day key expiry:

Key expiry for tagged devices is disabled by default.

Tailscale docs, auth keys

It no longer belongs to your Tailscale user, which only matters if you use Tailscale SSH from it to your own devices. ClosedVPS servers use ordinary SSH that you start from your laptop, which the rule above allows. Two tagged servers can't reach each other either, until you add a rule from tag:closedvps to tag:closedvps.
